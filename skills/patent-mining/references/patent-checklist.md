# Patent Quality Checklist

Use this checklist to validate identified innovations before generating disclosure documents.

## 1. Novelty Check

- [ ] **No exact match in prior art** — Searched and found no identical solution
- [ ] **Different from standard implementations** — Not just using a library as intended
- [ ] **Unique combination** — If combining known techniques, the combination itself is novel
- [ ] **Solves problem differently** — Approaches the problem from a new angle

## 2. Non-Obviousness Check

- [ ] **Not a trivial modification** — More than just changing parameters
- [ ] **Unexpected results** — Achieves something surprising or counterintuitive
- [ ] **Technical challenge overcome** — Required solving a non-trivial problem
- [ ] **Expert wouldn't arrive easily** — A skilled practitioner wouldn't immediately think of this

## 3. Utility Check

- [ ] **Practical application** — Has real-world use cases
- [ ] **Measurable benefit** — Quantifiable improvement (speed, accuracy, cost)
- [ ] **Works as described** — Implementation actually functions
- [ ] **Reproducible** — Can be implemented by others following the description

## 4. Enablement Check

- [ ] **Sufficient detail** — Enough information to implement
- [ ] **Clear description** — Technical approach is understandable
- [ ] **Source code available** — Can point to actual implementation
- [ ] **No hidden components** — All essential parts are documented

## 5. Technical Subject Matter

- [ ] **Not abstract idea** — Tied to specific technical implementation
- [ ] **Not natural phenomenon** — Artificial/engineered solution
- [ ] **Computer-implemented** — Has specific technical steps
- [ ] **Concrete result** — Produces tangible output

## Innovation Quality Assessment

### A. Technical Depth (0-25 points)

| Score | Description |
|-------|-------------|
| 20-25 | Multiple interacting subsystems, complex algorithms |
| 15-19 | Significant algorithmic complexity, multiple components |
| 10-14 | Moderate complexity, clear technical contribution |
| 5-9   | Simple but novel approach |
| 0-4   | Minimal technical depth |

### B. Business Value (0-25 points)

| Score | Description |
|-------|-------------|
| 20-25 | Critical competitive advantage, high market value |
| 15-19 | Significant differentiation, clear customer benefit |
| 10-14 | Moderate value, supports product positioning |
| 5-9   | Minor differentiator |
| 0-4   | Limited business impact |

### C. Defensibility (0-25 points)

| Score | Description |
|-------|-------------|
| 20-25 | Clearly distinct from all prior art, broad applicability |
| 15-19 | Good differentiation, some prior art but different approach |
| 10-14 | Differentiated but may face challenges |
| 5-9   | Some overlap with prior art |
| 0-4   | Significant prior art concerns |

### D. Implementation Evidence (0-25 points)

| Score | Description |
|-------|-------------|
| 20-25 | Production code, extensive documentation, test coverage |
| 15-19 | Working implementation, good documentation |
| 10-14 | Prototype, basic documentation |
| 5-9   | Partial implementation |
| 0-4   | Concept only |

**Total Score**: Sum of A + B + C + D

| Total | Recommendation |
|-------|----------------|
| 80-100 | Strong patent candidate, proceed immediately |
| 60-79 | Good candidate, proceed with disclosure |
| 40-59 | Moderate candidate, consider improvements |
| 20-39 | Weak candidate, may not be worth pursuing |
| 0-19 | Not recommended for patent |

## Prior Art Search Checklist

### Patent Databases

- [ ] **Google Patents** — patents.google.com
- [ ] **USPTO** — patft.uspto.gov
- [ ] **WIPO** — patentscope.wipo.int
- [ ] **EPO** — worldwide.espacenet.com

### Academic Sources

- [ ] **IEEE Xplore** — ieeexplore.ieee.org
- [ ] **ACM Digital Library** — dl.acm.org
- [ ] **arXiv** — arxiv.org
- [ ] **Google Scholar** — scholar.google.com

### Industry Sources

- [ ] **Competitor products** — Feature announcements, documentation
- [ ] **Open source** — GitHub, GitLab similar projects
- [ ] **Technical blogs** — Engineering blogs from similar companies
- [ ] **Product documentation** — Public API docs, user guides

## Disclosure Readiness Checklist

Before generating a disclosure document:

- [ ] Innovation clearly identified and described
- [ ] Source code locations documented
- [ ] Technical components enumerated
- [ ] Prior art search completed
- [ ] Differentiation clearly articulated
- [ ] At least one independent claim drafted
- [ ] Suggested drawings identified
- [ ] Inventors identified

## Submission Readiness Checklist

Before generating a submission presentation:

- [ ] Disclosure document completed
- [ ] Claims reviewed and refined
- [ ] Architecture diagram prepared
- [ ] Key features summarized (5-7 bullet points)
- [ ] Competitive differentiation clear
- [ ] Business value articulated
