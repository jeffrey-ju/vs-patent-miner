# Patent Writing Guide — USPTO & TIPO

Reference guide for writing patent-quality disclosure documents. Covers claim drafting, specification prose, forbidden language, and Traditional Chinese (繁體中文) terminology for Taiwan Intellectual Property Office (TIPO) filings.

## Claim Drafting Standards

### The Method / System / CRM Triad

Every software patent disclosure MUST include three independent claims covering the same inventive concept:

1. **Method claim** — "A computer-implemented method for [function], comprising: ..."
2. **System claim** — "A system comprising: a processor; and a non-transitory computer-readable medium storing instructions that, when executed by the processor, cause the processor to: ..."
3. **CRM claim** — "A non-transitory computer-readable medium storing instructions that, when executed by a processor, cause the processor to perform operations comprising: ..."

This triad ensures protection against infringement by anyone who (a) performs the method, (b) builds the system, or (c) distributes the software.

### Antecedent Basis Rules

Antecedent basis is the #1 source of USPTO rejections under 35 U.S.C. 112(b). Every noun phrase in a claim must be properly introduced.

**First mention — use "a" or "an":**
```
receiving a goal statement from a user interface
computing a first alignment score based on a set of strategy documents
```

**Subsequent mentions — use "the" or "said":**
```
comparing the goal statement against the set of strategy documents
generating, based on the first alignment score, a composite result
```

**Rules:**
- Never introduce a new element with "the" — if "the score" appears, "a score" must appear first
- Every element in a dependent claim must trace back to an element in its parent claim
- Use consistent terminology — once it is "goal statement", never switch to "objective text"
- Numbered elements (first, second, third) help distinguish similar elements
- "wherein" clauses further describe already-introduced elements; they do not introduce new steps

### Claim Scope Strategy

**Independent claims should be broad.** Capture the inventive concept without implementation details:

| Too narrow (avoid) | Broad (preferred) |
|---|---|
| "using cosine similarity on BERT embeddings" | "computing a similarity score using embedding-based semantic comparison" |
| "querying a PostgreSQL pgvector table" | "retrieving documents from a vector database" |
| "using an LRU cache of size 256" | "caching computed scores to reduce redundant computation" |

**Dependent claims narrow the scope.** Add implementation specifics one layer at a time:
- Claim 4 (depends on 1): "...wherein the similarity score is computed using cosine similarity"
- Claim 5 (depends on 4): "...wherein the embeddings are generated by a transformer-based language model"

### Claim Language Patterns

**Preamble patterns:**
- "A computer-implemented method for [gerund phrase], comprising:"
- "A system for [gerund phrase], the system comprising:"
- "A non-transitory computer-readable medium storing instructions..."

**Step patterns (use gerunds with active structure):**
- "receiving, by a processor, [input] from [source];"
- "computing, by the processor, a [result] by [technique];"
- "determining, by the processor, whether [condition];"
- "in response to determining that [condition], performing [action];"
- "generating, by the processor, [output] based on [inputs]."

**Transition words:**
- "comprising" — open-ended, allows additional elements (preferred for independent claims)
- "consisting of" — closed, limits to exactly listed elements (avoid unless intentional)
- "consisting essentially of" — middle ground (rarely used in software patents)

## Specification Prose Standards

### Forbidden Language

These phrases cause real legal damage during patent prosecution and litigation:

| Forbidden | Risk | Replacement |
|---|---|---|
| "the invention" | Courts limit ALL claims to described scope | "the disclosed method", "the system" |
| "the present invention" | Same — prosecution history estoppel | "in some implementations", "in one embodiment" |
| "always", "never", "must" | Absolute language limits claims | "in one embodiment", "may", "can" |
| "obviously", "simply", "easily" | Admission against patentability (35 USC 103) | Remove entirely |
| "important", "critical", "key" | Implies unlisted features are non-essential | Remove or rephrase neutrally |
| "preferred embodiment" | Courts may limit claims to preferred form | "in one embodiment", "in some implementations" |
| "the best mode" | Triggers best mode requirement issues | Describe without labelling as "best" |

### Specification Structure

The detailed description should follow this pattern:

1. **System overview** — high-level architecture, no value judgments
2. **Component descriptions** — each component in its own section
3. **Process flow** — step-by-step operation, matching claim steps
4. **Alternative embodiments** — "In some implementations..." variations
5. **Formulas/algorithms** — formal notation with variable definitions

**Every element mentioned in the claims must appear in the specification.** If Claim 1 mentions "a scope-weighted retrieval module", the specification must describe what it is and how it works.

### Prose Patterns

**Good:**
```
In some implementations, the system computes a strategic alignment score
by comparing an input goal statement against a plurality of strategy documents
retrieved from a vector database. Each retrieved document is assigned a weight
based on its organisational scope relative to the user.
```

**Bad:**
```
The invention's key innovation is its strategic alignment scoring engine.
This is obviously better than existing systems because it uses a sophisticated
scope-aware weighting algorithm that always produces accurate results.
```

### TIPO Abstract Rules

- Maximum 300 Traditional Chinese characters
- Single paragraph
- Must state: invention purpose, technical means, and primary effect
- Use formal register (書面語), not colloquial
- No figures or chemical formulae in the abstract

### TIPO Claim Formatting

- Claims are numbered continuously (第1項、第2項...)
- Independent claims use: "一種[noun]，其[verb]包含："
- Dependent claims use: "如申請專利範圍第N項所述之[noun]，其中[detail]。"
- Method claims: "一種[function]的方法，包含以下步驟："
- System claims: "一種[function]系統，包含：一處理器；及一非暫態電腦可讀媒體..."

## Quality Checklist

Before finalising any disclosure, verify:

- [ ] Abstract present (EN ≤ 150 words, TW ≤ 300 chars)
- [ ] Three independent claims (method + system + CRM)
- [ ] Antecedent basis correct in every claim
- [ ] No forbidden language ("the invention", "obviously", etc.)
- [ ] Every claim element described in specification
- [ ] Traditional Chinese uses TW terminology (not CN)
- [ ] Dependent claims properly reference parent claims
- [ ] Prior art section includes at least 2 reviewed systems
- [ ] Differentiation statement present
- [ ] Consistent terminology throughout (no synonym swapping)
